# AntiVishing 기획서

## 1. 프로젝트 개요

- **프로젝트명**: AntiVishing
- **한 줄 소개**: 은행 창구직원이 거래 접수 순간부터 보이스피싱 정황을 놓치지 않도록 돕는 AI 기반 실시간 이상거래 탐지·확인 보조 도구
- **제출 대회**: 2026 금융 AI Challenge (주최 금융보안원, 접수 마감 2026.09.07)
- **참가 형태**: MVP 프로토타입 웹서비스 (Python/FastAPI 백엔드 + React 프론트엔드, Claude API 기반 LLM 추론)

## 2. 문제 정의

보이스피싱은 여전히 피해 규모가 크고, 특히 은행 창구는 피해를 막을 수 있는 마지막 접점이다. 그러나 실제 현장에서는:

- 창구직원이 하루에도 수십 건의 거래를 처리하며, 매 건마다 보이스피싱 여부를 깊이 의심할 여유가 없다.
- 판단 기준이 개인 경험치에 의존해 직원마다 민감도가 다르다.
- 의심되더라도 고객을 어떻게, 어디까지 캐물어야 할지 표준화된 절차가 없어 과도하게 캐묻거나(고객 불만) 혹은 형식적으로 넘어가는(피해 방지 실패) 양극단이 발생한다.
- 이미 송금이 완료된 뒤에는 골든타임(지급정지 가능 시간) 내에 신속한 조치가 필요하지만, 이 판단·조치 프로세스도 표준화돼 있지 않다.

## 3. 타겟 사용자

**은행 영업점 창구직원.** IT/보안 전문가가 아니며, 바쁜 업무 중 짧은 시간 안에 판단해야 한다. 따라서 UI는:

- 전문 용어·raw 데이터를 전면에 노출하지 않는다 (필요하면 "자세히 보기"로 접어둔다).
- 다음에 뭘 해야 하는지 항상 한 가지 액션만 명확하게 보여준다 (버튼 난립 금지).
- 위험도를 색상·배지로 즉시 인지 가능하게 한다.
- 고객을 응대하는 동시에 화면을 봐야 하므로, 한 화면에 정보가 몰리지 않고 순차적으로만 진행된다.

## 4. 솔루션 개요 — 단계형 탐지·확인 파이프라인

거래 접수 → **Tier1(경량 실시간 필터)** → 의심 시 **Tier2(자동 심층 조사: 상대계좌 입출금 내역 분석)** → 애매하면 **저마찰 확인 절차(STT 코칭감지 → Y/N → 자유텍스트 LLM 대조)** → **최종 판정(XAI 설명)** → **고위험 시 에스컬레이션 조치(골든타임 지급정지 포함)**.

핵심 설계 원칙은 "합리적 의심이 없으면 고객을 귀찮게 하지 않는다"이다. 대부분의 정상 거래는 Tier1에서 즉시 종료되고, 애매한 거래만 추가 확인 절차를 거친다.

## 5. 차별점

- **상대 계좌 실거래 분석**: 하드코딩된 위험 플래그가 아니라, 실제 입출금 내역(CSV)을 파싱해 즉시인출비율·분산입금·심야거래 비중 등을 규칙기반으로 채점하고, 규칙에 없는 이상 패턴(예: 소액 반복 거래=구조화 의심)은 정상계좌 표본 대비 통계적 이상탐지(z-score)로 보완 포착한다.
- **STT 자동 트리거**: 첫 송금·고액·수취계좌 이상신호가 겹치는 순간, 직원이 버튼을 누르지 않아도 음성인식이 자동 시작되고 화면에 고지 배너가 뜬다.
- **논리적으로 일관된 LLM 확인 대화**: 자유텍스트 후속 질문은 최대 2회로 제한되며, 이전 대화 내역을 프롬프트에 그대로 제공해 이미 답한 내용을 다시 묻지 않고, 고객이 알 수 없는 정보(계좌 소유자 정보 등)나 아직 존재할 수 없는 서류(결제 전 영수증 등)를 요구하지 않도록 명시적으로 제약한다.
- **XAI**: 최종 판정 근거를 룰/LLM 신호를 종합해 자연어 3~4문장으로 설명, 창구직원이 고객에게 바로 설명할 수 있다.
- **골든타임 대응**: 이미 송금이 완료된 케이스도 별도 플로우로 지급정지 요청까지 이어진다.

## 6. UI 리디자인 방향 (이번 작업 범위)

- **톤앤매너**: 금융권 특유의 신뢰감(안정적인 색상, 과하지 않은 장식) — 스타트업/토이 프로젝트 느낌 지양.
- **사용성**: 현업 창구직원이 처음 봐도 헷갈리지 않는 매우 쉬운 UI. 쓸모없는 버튼·선택지 최소화, 매 순간 "지금 할 일"이 하나로 좁혀져 보여야 함.
- **범위**: 색상 팔레트, 타이포그래피, 여백/그리드를 포함한 전체 리디자인. 정보 구조(단계, 화면 흐름)는 유지.
