# AntiVishing 기능명세서

## 1. 전체 사용자 플로우

```
[거래 접수]
    │  ① 고객 이름 + 본인 계좌번호 입력 → 고객 조회(신분증 스캔 시뮬레이션)
    │  ② 수취 은행 + 수취 계좌번호 입력 → 수취계좌 조회
    │  ③ 송금액 + 이미 송금 여부 입력
    │  (프로토타입은 사전 등록된 테스트 고객/계좌 조합에서만 실제 분석 결과가 나오며,
    │   등록되지 않은 조합은 실제 창구처럼 "조회할 수 없음"으로 처리된다.
    │   화면에는 어떤 조합이 정상/의심 케이스인지 힌트를 노출하지 않는다.)
    ▼
[Tier1 · 경량 실시간 필터]  (자동, 즉시)
    │  신뢰 수취인 여부 / 첫 거래 여부 / 평소 대비 금액 배율
    │
    ├─ 저위험 ──────────────────────────────────► [즉시 완료]
    │
    ▼ 애매/의심
[Tier2 · 심층 조사]  (자동, 상대 계좌 입출금 내역 분석)
    │  규칙기반 스코어링 + 통계적 이상탐지 + 조기경보DB + 사업자등록 진위
    │
    ├─ 강한 자동 신호(high_auto_signal) → STT 음성인식 자동 시작
    │
    ▼
[확인 절차]
    ① STT: 통화 중 코칭 정황 텍스트 분석
        │
        ├─ 강한 코칭 정황 감지 → [하드블록] ──────────► [최종 판정: 위험 높음]
        │
        ▼ 정황 없음/생략
    ② Y/N 질문 2문항 (아는 사람/사업체인가요? / 용도를 알고 계신가요?)
        │
        ├─ 둘 다 "예" → [최종 판정: 위험 낮음]
        │
        ▼ 하나라도 "아니오"
    ③ 자유텍스트 (LLM 사기 스크립트 패턴 대조, 최대 2회 후속질문)
        │
        └─ risk_level high/low 확정 시 → [최종 판정]
    ▼
[최종 판정]  위험도(low/high) + XAI 자연어 설명
    │
    ├─ 위험 낮음 → 종료
    │
    ▼ 위험 높음
[에스컬레이션 조치]
    - 송금인 설명·진행여부 확인
    - 내부/금감원 에스컬레이션
    - 보호자 참고 알림
    - (이미 송금된 경우) 골든타임 내 자동 지급정지 요청
```

## 2. 화면 구성 요소

### 2.1 헤더
서비스명 + 한 줄 설명 고정 표시.

### 2.2 진행 단계 표시기 (StepIndicator)
5단계: 거래접수 → 자동심사 → 확인 → 최종판정 → 조치. 현재 케이스 상태(status)에 따라 각 단계가 `done`(완료) / `active`(진행중) / `skipped`(건너뜀) / `pending`(대기)으로 표시된다. 저위험 즉시완료 케이스는 "확인"·"조치" 단계가 스킵 처리된다.

### 2.3 거래 접수 (TransactionForm)
케이스가 없을 때만 노출. (※ 아래는 목표 동작 정의이며, 프론트엔드 구현은 디자인 레퍼런스 확정 후 별도 진행)
- 입력 필드: 고객 이름, 고객 본인 계좌번호, 수취 은행, 수취 계좌번호, 송금액, 이미 송금 여부(체크박스)
- 시나리오 카드/드롭다운 선택 방식은 폐지되었다. 창구직원이 실제 업무처럼 값을 직접 입력한다.
- 고객 이름+계좌번호 입력 시 `/api/customer-lookup`으로 조회해 고객 프로필(나이/성별/잔액/최근채널/특이동향)을 표시할 수 있다(신분증 스캔 연출 대체).
- "거래 접수" 버튼 → `/api/cases` 호출, 케이스 생성과 동시에 Tier1/Tier2 즉시 실행됨
- 고객 또는 수취계좌가 등록된 테스트 데이터와 일치하지 않으면 404 에러 메시지를 그대로 노출("일치하는 고객 정보를 찾을 수 없습니다" / "조회할 수 없는 수취 계좌입니다")

### 2.4 요약 바 (SummaryBar)
케이스 생성 후 항상 상단 고정 노출. 고객명·수취인·금액·(이미 송금됨 배지)·현재 상태 뱃지·"새 거래 접수"(리셋) 버튼.

### 2.5 확인 절차 패널 (VerificationPanel)
`next_action` 값에 따라 아래 중 하나만 렌더링된다 (동시에 여러 액션을 보여주지 않음).

**① STT 블록** (`next_action = stt_optional_or_yesno`)
- `tier2.high_auto_signal = true`인 케이스는 화면 진입과 동시에 브라우저 음성인식(Web Speech API, ko-KR)이 자동 시작되고, "이상거래 정황이 감지되어 상담 내용이 자동으로 기록됩니다" 고지 배너가 표시된다.
- 그 외 케이스는 선택사항으로 안내만 표시, 직원이 필요시에만 실행.
- 인식 중에는 파형 애니메이션 + "음성 인식 중..." 표시, 중지/재시작 버튼 제공.
- 마이크 권한 거부/무음성/장치없음/네트워크 오류 등 실패 사유를 사람이 읽을 수 있는 한국어 메시지로 표시.
- 브라우저 미지원 시 텍스트 직접 입력으로 안내 전환.
- 인식된(혹은 직접 입력한) 텍스트를 "STT 분석 실행" 버튼으로 제출.

**② Y/N 블록** (`next_action`에 STT와 함께 노출, 또는 `yesno` 단독)
- "아는 사람/사업체인가요?", "이 돈의 정확한 용도를 알고 계신가요?" 각각 예/아니오 버튼.
- 둘 다 예를 선택하고 제출하면 즉시 저위험 종료로 이어질 수 있음.

**③ 자유텍스트 블록** (`next_action = freetext`)
- 최초 질문 "상황을 간단히 말씀해주세요" 또는 LLM이 생성한 후속 질문 표시.
- 고객 답변(직원이 대신 입력)을 텍스트박스에 입력 후 제출 → LLM이 알려진 사기 스크립트 패턴과 대조.
- 후속질문은 최초 답변 포함 최대 3라운드(=추가 질문 최대 2회)까지만 허용, 이후에는 강제로 최종 판정으로 넘어감.

**④ 에스컬레이션 블록** (`next_action = high_risk_actions`)
- 4개 조치 버튼: 송금인 설명·진행여부 확인 / 내부·금감원 에스컬레이션 / 보호자 참고 알림 / (이미 송금된 경우만) 골든타임 내 자동 지급정지 요청.
- 여러 조치를 순서 상관없이 복수 선택 가능(각각 로그에 누적 기록).

### 2.6 결과 카드 (ResultCard)
`final_decision`이 존재하면 노출. 위험 높음/낮음 배지 + LLM이 생성한 XAI 자연어 설명 3~4문장.

### 2.7 상세보기 패널 (PipelineView)
기본은 접힌 상태(`<details>`), 클릭 시 펼쳐서 아래를 원시 데이터 그대로 노출:
- Tier1 결과 및 사유
- Tier2 결과: 상대 계좌 라벨/계좌번호, 의심 스코어, 계산된 특징치(즉시인출비율/72h 입금상대수/심야비중/일평균거래), 사유 리스트(규칙기반 + 통계적 이상탐지 라벨 구분)
- 직원-고객 간 실제로 오간 전체 대화(질문-답변 쌍, STT/Y-N/자유텍스트 모두 포함)
- STT 코칭 정황 분석 결론, Y/N 결론, 자유텍스트 LLM 대조 결론

## 3. 케이스 상태값(FSM)

| status | 의미 | next_action |
|---|---|---|
| `TIER1_LOW_RISK_COMPLETED` | Tier1에서 저위험으로 즉시 종료 | `none_completed` |
| `TIER2_ESCALATED` | Tier2까지 확대, 확인 절차 대기 | `stt_optional_or_yesno` |
| `AWAITING_YESNO` | STT 완료(코칭 없음) 후 Y/N 대기 | `yesno` |
| `AWAITING_FREETEXT` | Y/N에서 애매 판정, 자유텍스트 대기 | `freetext` |
| `STT_HARD_BLOCKED` | STT에서 강한 코칭 정황 감지, 질문 없이 즉시 고위험 확정 | `high_risk_actions` |
| `FINAL_HIGH_RISK` | 최종 위험 높음 확정 | `high_risk_actions` |
| `FINAL_LOW_RISK` | 최종 위험 낮음 확정 | `none_completed` |
| `GOLDEN_TIME_FREEZE_REQUESTED` | 이미 송금된 고위험 건에 지급정지 요청 완료 | - |

## 4. 비즈니스 로직 요약

### 4.1 Tier1 (경량 실시간 필터)
- 등록된 신뢰 수취인이면 별도 확대 없이 저위험 처리.
- 신뢰 수취인이 아니면: 평소 최대 거래액 대비 1.5배 이상, 또는 (첫 거래이면서 일정 금액 이상)일 때 Tier2로 확대.
- **고령 금융소비자 보호(신규)**: 고객이 만 65세 이상(금융소비자보호법 시행령 제2조 기준 "고령금융소비자")이면, 위 "첫 거래 확대 기준 금액"이 50만원이 아니라 30만원으로 낮아진다. 보이스피싱 표적이 고령층에 집중되는 현실을 반영한 조치다.

### 4.2 Tier2 (심층 조사, 자동)
상대 계좌의 실제 입출금 내역(CSV)을 분석해 계산한 특징치에 규칙기반 점수를 매기고, 조기경보DB·사업자등록 확인 결과, 통계적 이상탐지 결과, 고령 금융소비자 여부를 더해 0~100점 스코어를 산출한다.

- 즉시인출비율(입금 후 6시간 내 인출 비중) 80% 이상 → +30점
- 최근 72시간 내 서로 다른 입금 상대 5명 이상 → +15점
- 심야(23시~06시) 거래 비중 40% 이상 → +10점
- 조기경보DB 등재 이력 있음 → +50점
- 사업자등록 진위확인 통과 → -40점
- 통계적 이상탐지: 위 규칙과 무관하게 정상계좌 표본 대비 어떤 지표든 3표준편차 이상 벗어나면 +20점 (알려지지 않은 패턴 포착용 보조 레이어). 정상계좌 표본 평균/표준편차 중 "분산입금 건수(72시간 내)"는 AI-Hub 실측 데이터로 갱신되었다. "일평균 거래빈도"·"즉시인출비율"·"심야거래비중"은 실측 데이터의 관측 기간(수개월)이 데모용 CSV의 관측 기간(수일)과 달라 절대값을 그대로 옮기면 정상 계좌까지 오탐지되는 것을 확인했으므로, 프로토타입 단계 가정치를 유지한다(자세한 근거는 `backend/app/pipeline/account_analysis.py` 주석).
- **고령 금융소비자 가산(신규)**: 위 규칙기반 점수 또는 통계적 이상탐지 중 하나라도 이미 걸린 경우에 한해, 고객이 만 65세 이상이면 +10점을 추가한다. 계좌 자체가 깨끗한데 고객이 고령이라는 이유만으로 점수를 올리지는 않는다(계좌 위험도와 무관한 신호를 섞지 않기 위함).
- 70점 이상이면 `high_auto_signal = true` → STT 음성인식 자동 트리거

### 4.3 STT 코칭 정황 판정 (2단계: 로컬 분류기 → Claude)
채록된 텍스트는 먼저 자체 파인튜닝한 로컬 분류기(klue/roberta-small, `ml/train_coaching_classifier.py`, 현재 v5.1)를 거친다.
- 로컬 분류기가 보이스피싱일 확률을 5% 미만으로 강하게 낮게 판단하면(`SKIP_LLM_THRESHOLD`) Claude 호출 없이 즉시 "정상"으로 처리한다(비용·속도 절감).
- 그 외(조금이라도 애매하거나 의심스러운 경우)에는 항상 Claude(`analyze_stt_transcript`)로 넘겨 최종 판단을 받는다. LLM이 텍스트에서 "제3자가 실시간으로 지시하는 정황"을 판별해 `coaching_detected=true`이고 신뢰도 0.7 이상이면 하드블록(질문 절차 없이 즉시 고위험 확정).

로컬 분류기는 최종 판정자가 아니라 보수적인 1차 게이트다. 학습 데이터 구성, v1~v5.1 개선/실패 이력, held-out 성능, 남은 한계(짧고 구체성 낮은 문자 기반 가족 사칭 일부 미탐 등)는 `ml/README.md` 참고.

### 4.4 Y/N 확인
두 질문 모두 "예"인 경우에만 "명확히 정상"으로 판정, 그 외는 자유텍스트 단계로 진행.

### 4.5 자유텍스트 LLM 패턴 대조
알려진 4개 사기 스크립트 패턴(검찰/금감원 사칭, 가족 사칭, 투자 사기, 정상 사업자 할인)과 고객 진술을 대조. 후속 질문 시 다음을 반드시 지킨다: 이미 나눈 대화 반복 금지, 고객이 알 수 없는 정보(계좌 소유자 정보 등) 요구 금지, 아직 존재할 수 없는 서류(결제 전 영수증) 요구 금지, 후속질문 최대 2회.

### 4.6 최종 판정 우선순위
1. STT 강한 코칭 감지 → 고위험
2. 자유텍스트 risk_level=high → 고위험
3. Y/N 명확히 정상 → 저위험
4. 자유텍스트 risk_level=low → 저위험
5. (판단 근거 부족 시) Tier2 자동 신호 강도로 보수적 판정

판정 후 LLM이 모든 신호를 종합해 XAI 자연어 설명을 생성.

## 5. 테스트 데이터로 재현 가능한 6가지 케이스

더 이상 화면에서 선택하는 "시나리오 ID"가 아니라, 사전 등록된 고객·수취계좌 조합(이름+계좌번호)을 입력했을 때 재현되는 케이스다. 구체적인 이름/계좌번호는 화면에 노출하지 않으며, `docs/03_API명세서.md` 부록(평가자용, 화면 비노출)에서만 확인할 수 있다.

| 성격 | 송금액(참고) | 기송금 | 예상 흐름 |
|---|---|---|---|
| 정상 송금(신뢰 수취인) | 40만원 | 전 | Tier1 저위험 즉시 완료 |
| 검찰 사칭·안전계좌 | 2,500만원 | 전 | Tier2 고위험(100점) → STT 하드블록 |
| 가구점 할인(선의) | 80만원 | 전 | Tier2 저위험(0점) → Y/N·자유텍스트에서 정상 확인 |
| 대포통장 의심(투자 사기) | 900만원 | 전 | Tier2 고위험(75점, 고령 가산 포함) → STT 하드블록 또는 자유텍스트 |
| 자녀 사칭(고령층 첫거래) | 300만원 | 전 | Tier2 자동신호 없음(0점) → 자유텍스트에서 고위험 |
| 이미 송금 완료(골든타임) | 1,800만원 | 후 | Tier2 고위험(100점) → 골든타임 지급정지 요청 |

송금액과 기송금 여부는 시나리오에 고정되어 있지 않고 창구직원이 매번 직접 입력하는 값이다. 위 표의 금액은 각 케이스의 의도된 위험도가 재현되도록 데모에서 사용을 권장하는 참고값이다.

## 6. 디자인 시 고려할 사용성 요구사항

- 한 화면에는 항상 "지금 해야 할 일" 하나만 강조되어야 한다 (STT/Y-N/자유텍스트/에스컬레이션을 동시에 나열하지 않음, 현재 구조 유지).
- 위험도는 색상만으로도 즉시 구분 가능해야 한다 (고위험=경고색, 저위험=안전색).
- raw 데이터·점수·사유 리스트는 기본적으로 숨기고 "자세히 보기"로만 노출한다.
- 버튼은 현재 단계에서 실제로 눌러야 하는 것만 노출한다(에스컬레이션 4종처럼 여러 선택지가 필요한 경우를 제외하고 원칙적으로 1액션 1버튼).
- 전문 용어(Tier1/Tier2, 스코어, z-score 등)는 기본 화면에는 노출하지 않고, 상세보기에서만 사용한다.
