# 코칭탐지 로컬 분류기

STT 자유텍스트에서 "제3자가 실시간으로 지시(코칭)하고 있다는 정황"을 잡아내는
1차 로컬 필터. `backend/app/pipeline/stt_analysis.py`에서 사용한다.

## 데이터 (3종)

1. [KorCCViD_v1.3.csv](https://github.com/selfcontrol7/Korean_Voice_Phishing_Detection) —
   실제 통화 전사, 정상 609 / 보이스피싱 121건.
2. 같은 저장소의 `df_data_vishing.csv` — 추가 보이스피싱 전사. v1.3과 중복 제거 후
   **신규 610건**을 확보해 보이스피싱 표본을 총 731건까지 늘렸다.
3. AI-Hub "민원(콜센터) 질의-응답 데이터" 금융보험 도메인에서 추출한 정상 고객 발화
   **248건** (`data_prep/finance_normal_samples.json`, 이미 저장소에 포함).

최종 학습셋: 정상 857 / 보이스피싱 731 (약 1.17:1, 거의 균형).

## 모델 & 학습

- `klue/roberta-small` (한국어 사전학습, 약 68M 파라미터 — CPU 파인튜닝 가능한 크기)
- weighted cross-entropy (지금은 클래스 비율이 거의 1:1이라 가중치 영향은 미미함)
- train/val/test = 7:1.5:1.5 (stratified, seed=42)
- 실행: `KorCCViD_v1.3.csv`, `df_data_vishing.csv`를 이 폴더에 받아둔 뒤
  `pip install -r ../backend/requirements.txt scikit-learn accelerate` →
  `python train_coaching_classifier.py`. CPU 4코어 기준 2 epoch 학습에 약 6~7분.

## 여기까지 온 과정 (실패 기록 포함, 정직하게 남김)

- **v1 (KorCCViD 121건만)**: held-out 100%였지만, 실제 은행 창구 발화("월세 보내드리는
  거예요")를 보이스피싱 99%+로 오분류. 원인: KorCCViD의 "정상" 표본이 전부 친구/가족
  잡담이라 금융 어휘 자체가 "정상"에 거의 없었음(모델이 "금융 어휘=보이스피싱"으로 편향).
- **v2 (정상 800건 추가, 2 epoch)**: 은행 발화 오분류는 고쳤지만, 클래스 비율이 11.6:1로
  벌어지면서 모델이 "학습에 쓴 보이스피싱 각본과 거의 똑같지 않으면 무조건 정상"으로
  붕괴. 실시간 코칭 정황("불러주는 대로 계좌번호 입력하고 있어요")까지 정상으로 오분류
  — v1보다 더 위험한 실패라 폐기.
- **v3 (정상 248건으로 축소, 1 epoch)**: 하이퍼파라미터만 조정한 시도. 클래스 비율을
  7:1로 완화했지만 근본 원인(보이스피싱 표본 121건의 다양성 부족)은 그대로라 동일한
  실패 패턴 반복. → **하이퍼파라미터 조정만으로는 해결 안 됨**을 확인.
- **v4 (현재)**: 보이스피싱 표본 자체를 731건까지 늘려 근본 원인을 데이터로 해결.

## 측정된 결과 (v4, 2026-08-27)

held-out test 239건(정상 129 / 보이스피싱 110) 기준 정확도 99%, 보이스피싱 recall 97%
(110건 중 3건 오분류, 전부 ASR 잡음이 심한 문장).

**실사용 문장 검증** (held-out 벤치마크가 아니라 직접 만든 문장으로 확인):

| 문장 | 보이스피싱 확률 |
|---|---|
| "이번 달 월세 보내드리는 거예요" (정상) | 0.1% |
| "적금 하나 새로 가입하고 싶은데요" (정상) | 0.1% |
| "지금 통화하면서 불러주는 대로 계좌번호 입력하고 있어요" (코칭 진행 중) | **92.2%** |
| "검찰청 수사관인데요... 안전계좌로 즉시 이체하셔야 합니다" (전형적 각본) | 99.9% |
| "엄마 나 폰 액정 깨져서... 돈 좀 보내줘" (문자 가족 사칭) | **0.1% (오탐, 놓침)** |

v1~v3에서 못 잡던 "코칭 진행 중" 발화를 이제 잡아낸다는 점에서 실질적인 개선이다.

**남은 한계**: "엄마 나 폰 고장나서 문자로 연락해" 류의 **문자/메신저 기반 가족 사칭**은
여전히 놓친다. 학습 데이터(KorCCViD, df_data_vishing)가 전부 **전화 통화** 전사라
말투가 격식체 콜센터 각본 위주이고, 문자 사칭 특유의 짧고 반말인 말투는 학습 데이터에
아예 없기 때문이다. 이건 추가로 문자 사칭 스타일의 라벨 데이터가 있어야 고칠 수 있는
문제라 지금은 알려진 한계로 남겨둔다.

## 그래서 이렇게 설계했다

`coaching_classifier.py`는 이 모델을 최종 판정자로 쓰지 않는다. "보이스피싱일 확률이
매우 낮다(<5%)"고 강하게 판단할 때만 Claude 호출을 생략하는 **보수적인 1차 필터**로만
쓰고, 조금이라도 애매하거나 의심스러우면 항상 Claude(`llm_client.analyze_stt_transcript`)로
넘겨 최종 판단과 근거 설명(XAI)을 받는다. v4로 개선됐어도 이 보수적 게이팅 구조는
그대로 유지한다 — 위 "문자 사칭" 한계처럼 아직 모르는 실패 사례가 더 있을 수 있어서다.

## 파일

- `train_coaching_classifier.py` — 학습 스크립트 (재현 가능)
- `data_prep/finance_normal_samples.json` — AI-Hub 금융보험 정상 발화 추출 결과 (재현용, 저장소에 포함)
- 학습된 가중치(`model.safetensors`, 약 260MB)는 용량 문제로 git에 커밋하지 않는다
  (`backend/app/models/coaching_classifier/`, `.gitignore` 처리됨). 필요하면 이
  스크립트를 다시 실행해 생성한다.
